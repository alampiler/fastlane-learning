# Stories

Журнал поломок для CI/CD-плану ([rn-cicd-learning-plan.md](https://github.com/alampiler/fastlane-learning)).
Формат: **що зламалось → як знайшов причину → що зробив → цифри**.


Примітка. Реліз андроїд. 
Ми прокидуємо в Actions secrets and variables в середині гіта - settings/secrets/actions секрети, по одному на один секрет.
Ці секрети тягнуться з створеного ключа. Сам ключ читається через base64 -i release.keystore | pbcopy.
Далі в build.gradle ми прокидуємо ці ключі як приховані аналоги env.
Коли буде запускатись cd реліз білд він буде тягнути ці зашифровані ключі з гіта.

## [Сесія 4] Firebase App ID 404 при заливці dev-збірки

- **Що зламалось:** `firebase_app_distribution` впав з `Invalid request, status_code: 404` при заливці dev-flavor APK.
- **Як знайшов причину:** Gradle-збірка (`assembleDevRelease`) пройшла успішно, впав лише крок заливки в Firebase — отже проблема в ідентифікаторі застосунку, не в білді. Звірив секрет `FIREBASE_APP_ID_DEV` з реальним App ID у Firebase Console (Project Settings → Your apps) — значення не збігалось.
- **Що зробив:** оновив секрет `FIREBASE_APP_ID_DEV` правильним App ID зареєстрованого dev-застосунку (`com.alampiler.fastlanelearning.dev`).
- **Цифри:** —

## [Сесія 4] Prod-збірка залита успішно, але лист тестувальнику не прийшов

- **Що зламалось:** `firebase_app_distribution` для prod відзвітував повним успіхом (Uploaded, Distributing, upload finished successfully) в логах CI, але email-нотифікація тестувальнику не прийшла (перевірено і Inbox, і Spam).
- **Як знайшов причину:** статус тестувальника на сторінці релізу в Firebase Console показував "Invited" (не помилку) — тобто Firebase зафіксував намір відправити. У веб-консолі тестувальника (appdistribution.firebase.google.com → All apps) застосунок висів у стані "Pending" з кнопкою "Accept Invitation" — сам email з цією кнопкою просто не долетів.
- **Що зробив:** прийняв запрошення вручну через веб-консоль тестувальника замість email-лінка — доступ і завантаження спрацювали одразу.
- **Цифри:** dev і prod встановлені на одному пристрої одночасно, окремими застосунками (різні `applicationId`/іконки) — фінальна мета Сесії 4 підтверджена.
